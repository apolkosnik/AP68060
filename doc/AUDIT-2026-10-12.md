# AP68060 CPU MMU FPU and bus audit

Six defects remain reproducible in the audited working tree: LPSTOP error termination, misaligned cache-fill fault metadata, RTE cache allocation, FPU overflow status, locked-bus handoff, and reset during bus ownership. A seventh observed mismatch, FSLW.TTR on bus errors, follows WinUAE but contradicts the manual and is listed separately.

The full program regression passes: 28 programs under ten bus configurations. A direct comparison with WinUAE SoftFloat agrees on all 12,000 numerical results, but reports 65 exception-status mismatches, all explained by the FPU finding below. Passing the existing tests does not establish compliance for the failing cases.

Production RTL and existing tests were not edited by this audit. Reproducers, captured sources, reference-vector generator, and logs are under [obj/audit-2026-10-12](/home/adam/AP68060/obj/audit-2026-10-12). That directory is ignored by Git; preserve it separately if moving the report to another checkout.

## Fix status (2026-10-12)

All six findings were reproduced on the working tree and are fixed. Each has a regression test in `tb/run_tests.sh` that fails without its fix (checked against the earlier simulator, or against a build with only that fix reverted):

| 2 MA on a later fill beat | MA also when the operand's first long word arrived (`bo_got[e_va[3:2]]`) | t_cache060 12-14 (bench `$F15E`: one-shot TEA on a data read of a chosen long word) |

| 6 Reset from explicit ownership | The BIU runs the end of tenure during reset (BTT a bus clock asserted, one negated; BB and TIP driven negated before three-state) | t_halt phases 2-3 (bench `$F168`: a timed reset while the 68060 owns the bus); the bench counts the BTT pulse and checks BB/TIP release on every reset |

The follow-up audit ([AUDIT-2026-10-12-followup.md](AUDIT-2026-10-12-followup.md)) found that finding 6's fix still let a reset begin between bus clock edges at half-rate BCLK; that is fixed there.

FSLW.TTR on a TTR-mapped bus error remains as WinUAE and `t_eredir` have it (TTR clear), against the manual's 8.4.4.3/8.4.5; this is an open choice, not changed here.

## 1 LPSTOP takes an access error when its broadcast receives TEA

The write completion path in [ap68060_dmu.sv:1661](/home/adam/AP68060/rtl/ap68060_dmu.sv:1661) turns every `bo_err` into a store access fault, including an LPSTOP broadcast (`m4.r.ack == 3`). The read completion path already handles IACK and breakpoint acknowledgements specially.

MC68060UM §7.8.2.1, pp. 7-38–7-39, requires either TA or TEA to terminate the LPSTOP broadcast and enter low-power stop. Retry requests rerun the broadcast. TEA is therefore a successful completion condition for this instruction, not an operand write fault.

The probe runs the existing `t_halt` program with `+audit_lps_tea`. The testbench asserts TEA only on the broadcast to `$FFFFFFFE`. The core starts access-error stacking, fetches vector 2, and fails test 98; it also violates the existing monitor that requires a quiet bus after the broadcast. See [lpstop_tea-normal.log](/home/adam/AP68060/obj/audit-2026-10-12/lpstop_tea-normal.log).

This prevents low-power entry on a permitted termination and can leave a system accessing peripherals that have acted on the stop broadcast. Handle this acknowledge write separately in `E_W_DONE`. Newly added IACK and BKPT TEA probes pass, confirming that the failure is specific to the LPSTOP write path. WinUAE does not provide a pin-level termination oracle here.

## 2 A misaligned operand fault on a later cache-fill beat loses FSLW MA

[ap68060_dmu.sv:1951](/home/adam/AP68060/rtl/ap68060_dmu.sv:1951) sets MA in the fill-error path only from `e_part`, which indicates crossing a cache-line boundary. A misaligned operand can span two long words within the same line. If its first long word arrives and the second faults, `e_part` remains zero even though the fault is on a later access of the operand.

[fill_misaligned_ma.s](/home/adam/AP68060/obj/audit-2026-10-12/fill_misaligned_ma.s) loads a long word at `$9001`. The line fill starts at `$9000`; the testbench terminates `$9004` with TEA. The frame preserves FA=`$9001`, but reports FSLW=`$01050020` instead of `$09050020`: RE is set and MA is missing. Both burst and burst-inhibited runs fail. See [fill_misaligned_ma-normal.log](/home/adam/AP68060/obj/audit-2026-10-12/fill_misaligned_ma-normal.log).

MC68060UM §8.4.4.3, p. 8-22, defines operand MA as a fault on the second or later access of a misaligned transfer. §5.7.1 specifically identifies a missing second part of a misaligned operand as a reason for a later line-fill error to fault. WinUAE's `misalignednotfirst()` in [cpummu.cpp](/home/adam/WinUAE/cpummu.cpp) likewise adds MA for the later operand access.

The [cache-disabled control](/home/adam/AP68060/obj/audit-2026-10-12/split_misaligned_ma_control.s) passes for the same operand and failing address. The earlier fix covers ordinary split transfers and crossing a line, but not this cache-fill case. Preserve the fill's progress when constructing FSLW so fault handlers can distinguish the two cases correctly.

## 3 RTE stack reads allocate data-cache lines

The RTE microcode in [ucode.py:414](/home/adam/AP68060/tools/ucode.py:414) issues ordinary reads for the format word, SR, and PC. [ap68060_backend.sv:535](/home/adam/AP68060/rtl/ap68060_backend.sv:535) asserts `dm_noalloc` only for `MFC_SUP`; these RTE reads do not carry it. A cold RTE frame therefore causes a line fill and allocation.

MC68060UM §5.4.3, p. 5-9, excludes exception-stack misses from allocation. §7.7.1, p. 7-13, explicitly includes exception-stack deallocation by RTE among accesses that do not allocate on a read miss. Existing cache hits should still be usable.

[rte_noalloc.s](/home/adam/AP68060/obj/audit-2026-10-12/rte_noalloc.s) creates a cold format-0 frame at `$9000`, enables the data cache, executes RTE, and then reads the frame as ordinary data. It observes four external read beats, all from the RTE's line fill. The required behavior is four operand transfers for RTE followed by four beats for the ordinary load's allocation. The [trace](/home/adam/AP68060/obj/audit-2026-10-12/rte_noalloc-normal.log) shows RTE issuing `SIZ=LINE` at `$9004`.

The [control](/home/adam/AP68060/obj/audit-2026-10-12/rte_noalloc_control.s), which temporarily sets CACR no-allocation during RTE, observes the expected eight reads and passes. Besides extra reads, allocation can evict and push an unrelated dirty line during exception return. Mark RTE's stack reads as nonallocating without disabling normal hit handling.

## 4 FMOVE OUT overflow always sets INEX2

The single and double packing paths unconditionally set FPSR bit 9 on overflow at [ap040_fpu.v:1459](/home/adam/AP68060/rtl/fpu/ap040_fpu.v:1459) and [ap040_fpu.v:1516](/home/adam/AP68060/rtl/fpu/ap040_fpu.v:1516). They calculate significand inexactness as `inx`, but disregard it in the overflow branch.

For an exactly representable significand that exceeds the destination exponent range, OVFL is set while EXC.INEX2 remains clear. Accrued INEX is still set by overflow. WinUAE explicitly implements that distinction in the `SOFTFLOAT_68K` branches of [roundAndPackFloat32](/home/adam/WinUAE/softfloat/softfloat.cpp:790) and [roundAndPackFloat64](/home/adam/WinUAE/softfloat/softfloat.cpp:975), and in the accrued-status logic in [fpp.cpp:639](/home/adam/WinUAE/fpp.cpp:639). MC68060UM §6.6.7 defines INEX2 in terms of excess significant bits; §6.6.4 separately describes overflow handling and the conditional involvement of the INEX handler.

[fpu_overflow_inex.s](/home/adam/AP68060/obj/audit-2026-10-12/fpu_overflow_inex.s) loads exactly `2**128` into FP0 and executes `FMOVE.S FP0,D0`. In the overflow handler, masked EXC status is `$1200`; WinUAE gives `$1000`. See [fpu_overflow_inex-normal.log](/home/adam/AP68060/obj/audit-2026-10-12/fpu_overflow_inex-normal.log). The default stored overflow result is not used to establish this finding: the manual permits an undefined hardware result before software support completes the operation.

The direct oracle covers 8,400 FADD, FSUB, FMUL, FDIV, FSQRT, FINT, and FINTRZ cases, plus 3,600 single/double output conversions, across the four rounding modes and three defined rounding precisions. All result bits match. All 65 status mismatches are output conversions reporting `$12` instead of `$10` in EXC; there are no other mismatches in this sample. This can mislead a handler that dispatches a lower-priority inexact exception from the saved status. Keep accrued INEX set on overflow, but derive EXC.INEX2 from actual significand inexactness.

## 5 Locked handoff omits the driven negated interval

When BGR permits a locked sequence to be interrupted, [ap68060_biu.sv:405](/home/adam/AP68060/rtl/ap68060_biu.sv:405) drops `a_oe`, raises LOCK/LOCKE, and asserts BTT on the same edge. The top-level interface groups bus attributes under `a_oe` and provides no separate LOCK/LOCKE output enable.

MC68060UM §§2.3.7–2.3.8, pp. 2-7–2-8, require an asserted LOCK or LOCKE to be driven negated for a full BCLK interval when relinquishing the bus, then three-stated one BCLK after the address bus is idled. Deasserting the output enable at the same edge as the signal does not produce that driven interval. This matters to external arbitration logic observing the end of a locked tenure.

[tb_bus_handoff.sv](/home/adam/AP68060/obj/audit-2026-10-12/tb_bus_handoff.sv) completes a locked read, then negates BG and asserts BGR. The [log](/home/adam/AP68060/obj/audit-2026-10-12/bus_handoff.log) confirms that LOCK first becomes negated when the shared output enable drops. Separate the lock-pin release timing from the address enable. This is distinct from the earlier LOCKE retry atomicity defect, which has been fixed.

## 6 Reset discards an explicit tenure without its required termination

The reset branch at [ap68060_biu.sv:261](/home/adam/AP68060/rtl/ap68060_biu.sv:261) immediately clears BB/TIP/BTT output enables and enters `B_RESET`. It bypasses the end-tenure sequence even when the processor explicitly owns the bus.

MC68060UM §7.11.2, p. 7-63, requires entering end tenure before reset when resetting from explicit ownership, so other masters can take the bus. §7.13 and figure 7-49, p. 7-73, require BB and TIP to be negated before becoming high impedance.

The handoff bench's `+reset` case establishes explicit ownership, completes a locked transfer, and asserts reset. [bus_reset.log](/home/adam/AP68060/obj/audit-2026-10-12/bus_reset.log) records both failures: BB is three-stated without a driven negated clock, and no BTT pulse appears during the next twelve clocks. A master relying on BTT to observe the end of the tenure can remain waiting; this consequence is inferred from the missing protocol event, rather than measured with a complete external arbiter.

Preserve the required reset-entry bus termination before releasing the outputs. The older concern about starting too soon after reset was not reproduced: the full core's first TS occurs 134 CLK edges after release, or 136 with BCLK at half CLK, beyond the manual's 27-CLK internal-reset interval. Those observations do not verify every reset waveform requirement.

## Manual and WinUAE disagreements

These should not be silently treated as reference agreement.

- **FSLW.TTR on a TTR-mapped bus error:** [ttr_bus_error.s](/home/adam/AP68060/obj/audit-2026-10-12/ttr_bus_error.s) reads `$F140` through DTT0 and receives TEA. It produces `$01050020`, with TTR clear. MC68060UM §8.4.4.3, p. 8-24, and §8.4.5, p. 8-25, require TTR set and explicitly list RE/WE among TTR faults. WinUAE and the repository's `t_eredir` assertions follow the current behavior. This is a reproduced manual mismatch, not a newly demonstrated difference from WinUAE.
- **Supervisor and write protection together:** the page-walk path checks WP before SP; the ATC-hit path checks SP before WP. WinUAE prioritizes SP. The manual describes both protections but does not clearly establish their simultaneous priority. The related question of ATC allocation on a supervisor-protection fault also remains unsettled by the differing passages. No new confirmed defect is claimed from those cases here.
- **Already documented deliberate choices:** alternate-space MOVES, data-side PLPA, and immediate abort at an upper write-protected descriptor now follow the manual where WinUAE differs. The current regression covers those fixes. The earlier FPU frame choices and remaining format/illegal-encoding questions in [AUDIT.md](/home/adam/AP68060/doc/AUDIT.md) should retain their separate reference qualification; they are not counted as newly reproduced defects in this report.

## Coverage and remaining limits

The final regression rechecks the earlier fixes for lost push errors, sustained snooping, locked table-history updates, LOCKE retries, ordinary misaligned bus errors, late line-fill errors, held level 7, PLPA, upper-table protection, FPU state/frames, and halt behavior. The newly observed MA failure is the additional case of a misaligned operand spanning two beats within one cache line.

Additional focused checks pass for PFLUSHAN/PFLUSHN preserving global entries, PFLUSH removing a selected global entry, TEA producing a spurious IACK vector, TEA preserving BKPT's illegal-instruction outcome, and TCI preventing repeated data-read allocation. These tests supplement the existing suite and do not cover all combinations of translation, snooping, retries, and fault injection.

WinUAE is used as a software-state and arithmetic reference, not a bus-waveform model. The SoftFloat sample does not establish exhaustive arithmetic correctness, NaN payload behavior, all exception-enable combinations, or software-support-package compatibility. The main bus slave inserts an extra response clock even in its nominal zero-wait configuration; genuine minimum-latency peripheral responses remain a coverage gap. Optional whole-CPU parameter combinations, hardware timing closure, and on-board behavior are outside these simulation results.
