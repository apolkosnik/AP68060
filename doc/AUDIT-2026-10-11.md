# AP68060 CPU MMU FPU and bus audit

The current core has nine reproduced functional defects, plus one additional MMU behavior that conflicts with the MC68060 manual but resembles WinUAE. The most serious defects lose cache writeback errors, lose snoop requests, and break the atomicity of locked operations. All 230 existing program regression runs pass, so those results do not establish compliance for these cases.

The audit covers integer execution and exceptions, MMU translation and history updates, FPU instruction and state handling, cache fault handling, and the external bus. It combines source comparison with focused Verilator simulations. RTL was not modified.

Audit inputs:

- AP68060 commit `2dac5a7dde424a7220ec5b0a636a8bfbe619e41e`.
- Local WinUAE commit `7d84eae9aecaf98bcfee1e5cf2c765d2fbfe17b4`; the cited reference files have no local changes.
- [MC68060UM.pdf](/home/adam/Downloads/MC68060UM.pdf), SHA256 `313fd672dfac8f1d1bb580ad61e8e1583a38b07fb4e2891aff7f29ef49d3ef40`. Manual page references below use the printed section page numbers.
- Default core parameters: `FPU_PIPE=0`, `LOOP_PRED=0`, `EARLY_RES=0`.

P1 indicates potential data loss, loss of coherency, broken atomicity, or unsafe fault recovery. P2 indicates other observable architectural incompatibility. Bus pin requirements are checked against the manual; WinUAE is not a pin timing oracle.

How the open questions were settled:

- Snooping: the tables of 7.11 (note 8) limit snooped transfers to one every two bus clocks, the probe's rate. A deeper queue cannot be enough, so the snooper keeps a copy of the data cache's tags and valid bits (in block RAM), written as the DMU writes its own. Each snooped line is checked a clock after its TS: a miss needs nothing, and a hit is invalidated by set and way in one frozen DMU clock, one per clock if need be. Only a line that may be waiting for its push goes through the full lookup, which also cancels the push; at most two such lines exist. The bench checks the copy against the cache on every snoop. The synthesis estimate did not grow (20,929 ALMs against 20,930).
- PLPA: the core follows appendix D, so PLPA uses the data TTRs and ATC whatever the DFC. With DFC 6 the probe's cached translation comes from the data ATC. WinUAE's DFC-based selection is listed in `doc/STATUS.md` as a known difference.
- Upper-table write protection: the core follows 4.2.6.3. The search ends with WP at the protected descriptor and its U is not set. WinUAE differs (listed in `doc/STATUS.md`).
- FPU state: an implemented instruction that reaches the FPU, the control register and FMOVEM reads included, moves NULL to IDLE. `FNOP; FSAVE` stays NULL, as in WinUAE.
- The FPU differential bench builds again (c02ec8a) and matches the sequential FPU on 100,000 random commands over four seeds.
- Unchanged: FSLW SIZE follows WinUAE's encoding; a write-protection fault allocates no ATC entry; PCR.EDEBUG has no debug interface; SAS shares the address bus's output enable.

The probes are run against the current simulator with `SIM=<build>/obj_prog/tb_ap68060 bash obj/audit/run_probes.sh`. The three module-level benches under `obj/audit` were updated locally for the current ports: the BIU's `halt`, `more` and `drop`, and the DMU's and snooper's tag-copy interface. `tb_snoop_rate.sv` now loads its 48 lines into the real DMU's tags and valid bits (and the snooper's copy) by backdoor before snooping them. It passes when every line has left the cache with no overflow. A snooper restoring the old six-clock path fails it as before: 24 of 48 serviced, overflow set.

## P1 Cache push bus errors are silently lost

[ap68060_dmu.sv:1834](/home/adam/AP68060/rtl/ap68060_dmu.sv:1834) starts a push with `e_ret = e_sret`. A bus error sets `bo_err`, but the CPUSH scan resumes without recording a pending push error. The line has already been invalidated or marked clean. `FSLW_PBE` is defined in the package but never used by the implementation.

The [push_bus_error.s](/home/adam/AP68060/obj/audit/push_bus_error.s) reproducer creates a dirty line at `$F140`, injects TEA into its CPUSHL write, and waits for an access error. Execution instead reaches failure code 2 with no exception. The [bus trace](/home/adam/AP68060/obj/audit/push_bus_trace.log) shows the push starting at cycle 794 and receiving TEA at cycle 796.

MC68060UM sections 5.7.2 and 8.4.6 require recording a push buffer bus error and delivering an access error with FSLW.PBE. Add a persistent push error indication, include it in exception arbitration, and preserve it until acknowledged. Test eviction, explicit CPUSH, dirty-line mode changes, and MOVE16 write faults separately.

## P1 Sustained snoops overflow the queue and lose invalidations

[ap68060_snoop.sv:91](/home/adam/AP68060/rtl/ap68060_snoop.sv:91) drops a new distinct address when the eight-entry data snoop queue is full. It sets `dc_ovf`, but this signal has no recovery path in the core. The normal testbench treats it as a simulation failure; hardware can continue using a line whose snoop was lost.

[tb_snoop_rate.sv](/home/adam/AP68060/obj/audit/tb_snoop_rate.sv) connects the real snooper to the real DMU and submits 48 distinct snoops, one every two clocks with BCLK equal to CLK. After draining, only 24 requests were serviced and overflow was asserted. This is legal transfer-start spacing for successive zero-wait bus cycles.

MC68060UM sections 2.6 and 5.6 require snoop hits to invalidate matching lines and give snooping priority over processor accesses. The design needs sufficient sustained service throughput or a correctness-preserving overflow strategy. Merely increasing the queue depth does not solve unbounded sustained traffic. The probe establishes lost requests; it does not depend on shared pages being copyback.

## P1 The final locked write loses protection before retry completes

[ap68060_biu.sv:379](/home/adam/AP68060/rtl/ap68060_biu.sv:379) assigns `locked <= !breq[pick_c].locke` when accepting a transaction. Thus, accepting the final LOCKE write clears the internal lock before the write succeeds. The retry path then permits relinquishing the bus when BG is negated, even with BGR negated.

[tb_lock_retry.sv](/home/adam/AP68060/obj/audit/tb_lock_retry.sv) completes a locked read, starts the final locked write, negates BG while leaving BGR negated, and requests a native TRA retry. The BIU asserts BTT and releases LOCK instead of preserving the atomic sequence.

MC68060UM sections 7.9.2 and 7.11.2, especially pages 7-49 and 7-60, require LOCK and LOCKE to survive this retry. Clear the internal lock only when the final transfer completes successfully, or when an error or explicitly allowed arbitration event ends the sequence.

## P1 MMU used bit updates omit the locked read

[ap68060_dmu.sv:1918](/home/adam/AP68060/rtl/ap68060_dmu.sv:1918) always reads descriptors with `lock=0`. When a U bit needs updating, [ap68060_dmu.sv:2019](/home/adam/AP68060/rtl/ap68060_dmu.sv:2019) writes the previously read value with LOCK and LOCKE asserted together. There is no protected reread before the update.

[tb_mmu_lock.sv](/home/adam/AP68060/obj/audit/tb_mmu_lock.sv) walks three descriptors with U clear. Its trace shows three unlocked reads followed by three individually locked writes, with zero locked reads. A second master can modify a descriptor between the initial read and write; the stale full-word write can then overwrite its change.

MC68060UM section 4.2.5 and table 4-1 require a complete locked read-modify-write sequence for these U updates. Reacquire the current descriptor under LOCK, merge the history bit into that value, and end the sequence with the write. Preserve the separate plain-write behavior specified for page-descriptor write accesses. WinUAE's descriptor helpers do not model external arbitration and cannot validate this requirement.

## P1 Misaligned bus faults omit FSLW MA

The bus-error paths at [ap68060_dmu.sv:1406](/home/adam/AP68060/rtl/ap68060_dmu.sv:1406) and [ap68060_dmu.sv:1520](/home/adam/AP68060/rtl/ap68060_dmu.sv:1520) construct FSLW without marking a fault on a later piece of an operand. The translation-fault path separately handles `e_part`, but these bus-error paths do not.

[misaligned_read.s](/home/adam/AP68060/obj/audit/misaligned_read.s) and [misaligned_write.s](/home/adam/AP68060/obj/audit/misaligned_write.s) access a long word at `$F13E` in cache-inhibited precise space. The first word succeeds; TEA is injected at `$F140`. Both exception frames have MA clear.

MC68060UM section 8.4.4.3 requires MA for the second or later access. Section 8.4.6 explains why this matters: a partially completed misaligned read-modify-write cannot safely restart. WinUAE explicitly sets the bit in [misalignednotfirst](/home/adam/WinUAE/cpummu.cpp:983). Track progress within both a line split and the smaller bus pieces inside a line; retain the original logical address in the frame.

## P2 An unrelated late cache fill error faults a completed operand

[ap68060_dmu.sv:1790](/home/adam/AP68060/rtl/ap68060_dmu.sv:1790) treats every failed line fill as if the requested operand did not arrive. The BIU exposes the error beat, but the top level does not route it to the DMU or fetch unit.

[late_fill_error.s](/home/adam/AP68060/obj/audit/late_fill_error.s) reads an aligned long word at `$F144`. That word arrives on the first fill beat; TEA occurs on the last, wrapping beat at `$F140`. The instruction incorrectly takes an access error, recorded as failure code 3.

MC68060UM section 5.7.1, pages 5-12 and 5-13, requires an exception only if the failed transfer contains data needed by the pending request. Track valid received bytes and distinguish loss of required data from failure to populate the rest of a cache line. [ap68060_fetch.sv:774](/home/adam/AP68060/rtl/ap68060_fetch.sv:774) has a similar unconditional fill-error path; the focused reproducer exercises the data side.

## P2 Lowering the interrupt mask does not recognize held level 7

[ap68060_backend.sv:1162](/home/adam/AP68060/rtl/ap68060_backend.sv:1162) excludes level 7 from the level comparison and recognizes it only through `nmi_edge`.

[nmi_mask_lower.s](/home/adam/AP68060/obj/audit/nmi_mask_lower.s) takes one level-7 interrupt at mask 7, returns with IPL still at 7, then executes `MOVE #$2600,SR`. The interrupt count remains one; a second interrupt is required.

MC68060UM section 8.2.9 and figure 8-3 explicitly specify this level-comparison case in addition to edge recognition. WinUAE's [interrupt check](/home/adam/WinUAE/newcpu.cpp:4866) includes both conditions. Permit held level 7 to qualify when the current mask is lower than 7 while retaining edge recognition at mask 7.

## P2 PLPA ignores cached instruction space translations

[ap68060_dmu.sv:1643](/home/adam/AP68060/rtl/ap68060_dmu.sv:1643) uses an ATC hit only when `isp` is false. For DFC 2 or 6, PLPA always starts a table search unless translation is transparent or disabled. There is no I-ATC lookup path for PLPA.

[plpa_cached.s](/home/adam/AP68060/obj/audit/plpa_cached.s) fills both ATCs with `$01000000 -> $8000`, changes the memory descriptor to `$9000` without PFLUSH, and executes PLPAR with DFC 6. The core returns `$9000`; the cached translation should still return `$8000`. Always walking can also create false faults when the cached translation remains usable but the descriptor has been removed.

MC68060UM section 4.7.3 requires using an existing ATC hit. Appendix D, page D-23, describes PLPA through the data TTR and ATC, whereas [WinUAE's PLPA implementation](/home/adam/WinUAE/cpummu.cpp:1456) selects instruction/data space using DFC. This probe populates both ATCs identically, so it fails under either reference interpretation. Resolve the space-selection discrepancy explicitly when adding the missing hit behavior.

## P2 FPU register reads leave the state incorrectly NULL

The control-register read path at [ap68060_fpif.sv:810](/home/adam/AP68060/rtl/ap68060_fpif.sv:810) and raw register read path at [ap68060_fpif.sv:835](/home/adam/AP68060/rtl/ap68060_fpif.sv:835) do not tell the FPU that an implemented instruction has executed. `fpu_used` consequently remains clear.

Starting from reset, both `FMOVE.L FPSR,D0; FSAVE frame` and `FMOVEM.X FP0,(A0); FSAVE frame` produce format `$00`. The expected format is IDLE `$60`. These sequences are reproduced by [fpu_read_cr.s](/home/adam/AP68060/obj/audit/fpu_read_cr.s) and [fpu_read_regs.s](/home/adam/AP68060/obj/audit/fpu_read_regs.s).

MC68060UM section 6.7 specifies the NULL-to-IDLE transition. WinUAE sets `fpu_state=1` at entry to [fpuop_arithmetic](/home/adam/WinUAE/fpp.cpp:3587), including these data-movement instructions. Add the state transition for successful implemented register-read operations without changing FPSR or FPIAR as a side effect.

## P2 Upper table write protection differs from the manual

This is a reproduced manual-conformance mismatch with a conflicting emulator reference, rather than an independently agreed defect.

[ap68060_dmu.sv:1951](/home/adam/AP68060/rtl/ap68060_dmu.sv:1951) accumulates an upper-level W bit, updates U, and continues walking. It does not check write protection until a resident final page descriptor is reached.

[root_write_protect.s](/home/adam/AP68060/obj/audit/root_write_protect.s) attempts a write through a valid, write-protected root descriptor whose pointer entry is invalid. The reported cause is PTB `$800`, rather than WP `$80`. The source path also updates the protected root's U bit before descending.

MC68060UM section 4.2.6.3, page 4-22, says to terminate immediately on encountering a protected descriptor during a write or read-modify-write search, without updating that descriptor's history bits. [WinUAE's walker](/home/adam/WinUAE/cpummu.cpp:690) also accumulates upper-level protection and continues. Prefer the manual's explicit rule for a conformance implementation, or settle the discrepancy with a real 68060 trace before adopting emulator behavior.

## Verification gaps and reference disagreements

The existing [FPU differential bench](/home/adam/AP68060/tb/tb_fpu_pipe.sv:85) cannot build. `tb/build_fpu_pipe.sh` reports 44 errors because the bench connects removed ports such as `fstate_unimp`, `fsave_ack`, and `pend_capture`. Its [build log](/home/adam/AP68060/obj/audit/fpu_pipe_build.log) is retained. Updating the bench interface is required before it can validate `FPU_PIPE=1`; comparing two versions of the same FPU would still not be an independent numeric oracle.

The reference disagreements require care:

- The manual's FSLW SIZE table disagrees with [WinUAE's documented encoding](/home/adam/WinUAE/include/mmu_common.h:55). The RTL follows WinUAE's encoding. This is not counted as a defect here.
- `FNOP; FSAVE` remains NULL in a separate probe. Section 6.7's general wording suggests IDLE, but [WinUAE explicitly keeps conditional operations NULL](/home/adam/WinUAE/fpp.cpp:2177). This is excluded from the confirmed FPU finding.
- Section 4.2.6.3 says write-protection failures do not allocate an ATC entry, whereas section 8.4.5 describes protection cases with an updated ATC. The existing core and tests choose no allocation. That conflict needs adjudication; it is not reported as a new confirmed defect.
- The existing [status document](/home/adam/AP68060/doc/STATUS.md) already records single issue and omitted BPE exceptions. Neither is counted as a new finding.

Additional interface limits are visible by inspection. PCR.EDEBUG is stored and read but has no output behavior; there is no JTAG/debug-pipe interface. SAS shares `a_oe` with the address bus, although section 2.4.3 specifies distinct output-enable timing when ownership starts and ends. These limits matter if physical pin compatibility is a requirement; they were not exercised by the focused simulations.

The 230-run baseline covers the default core configuration. This audit did not rerun the complete WinUAE 68060 instruction corpus, exhaustively compare FPU numeric results, fit the design, or validate physical setup and hold timing. The findings establish specific failures, not an exhaustive inventory of every possible mismatch.

## Reproducing the results

The baseline command was `JOBS=8 tb/run_tests.sh`; [regression.log](/home/adam/AP68060/obj/audit/regression.log) contains all 230 passing runs.

The twelve focused probes, covering the nine confirmed defects and the additional manual mismatch, can be rebuilt and run from the repository root:

```sh
bash obj/audit/run_probes.sh
```

The script exits nonzero while any of these defects remains. It uses the current `obj/obj_prog/tb_ap68060` binary for assembly programs; rebuild that binary with `tb/build_sim.sh` after changing the RTL. The three module-level benches are rebuilt by the script. [probe_summary.log](/home/adam/AP68060/obj/audit/probe_summary.log) contains the observed failures, and [provenance.json](/home/adam/AP68060/obj/audit/provenance.json) records the inputs. Reproducer sources and generated logs are local artifacts under ignored `obj/audit`; they are not tracked regression additions.

Fix the P1 bus, snoop, and fault-reporting defects first, then promote their reproducers into the maintained regression suite. Correct PLPA, interrupt recognition, and FPU state transitions next. Keep tests for reference disagreements separate until their expected behavior is settled.
